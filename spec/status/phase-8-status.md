# Phase 8 status

Status: **Implementation complete on Windows; full cross-platform gate not verified.** Phase 9 was subsequently implemented and is reported separately in `phase-9-status.md`.

The production CLI now uses the user's authenticated `codex exec` session by default, runs it read-only in an isolated temporary directory, and sends only the sanitized packet through stdin. No Reframe API key is required. The direct Responses API plus Windows DPAPI credential remains an explicit fallback. Automated tests use deterministic fake providers/transports, so no live Codex request or real credential was used. All named Phase 8 tests and supplementary provider tests pass on Windows; Unix remains not verified.

## Known limitations

- Full Windows-plus-Unix gate is not met because no Unix environment is available.

- Visual packet entries currently record explicit selected/surrounding/full-page capture and blur status; they do not yet transport captured image bytes to a live provider.
- The repository was already broadly dirty from Phases 0–7; `demo/vanilla-demo/style.css` is preserved user work and was not modified by Phase 8.
